# ระบบตรวจสินค้าใหม่ (RA)

เว็บสำหรับให้ฝ่ายจัดซื้อส่งข้อมูลสินค้าใหม่ให้ RA ตรวจ แล้ว RA กด Approve หรือ Reject
ข้อมูลและไฟล์ทั้งหมดเก็บใน Google Drive **แยกโฟลเดอร์ตามสินค้า**

เว็บ: https://naweevar-ui.github.io/New_Product/

## โครงสร้างใน Google Drive

```
RA ตรวจสินค้าใหม่/
├── สรุปรายการสินค้า              ← Google Sheet: 1 แถวต่อ 1 สินค้า (สถานะ, ผู้ส่ง, ลิงก์)
├── Mogu Drink/
│   ├── data.json                ← ข้อมูลทั้งหมดของสินค้านี้
│   ├── Ingredient - สูตร.pdf
│   ├── Nutrition - ฉลาก.png
│   ├── Process Flow - flow.pdf
│   └── Mogu Drink v1 สรุปข้อมูล  ← Google Doc สร้างตอนส่งให้ RA
└── ใบมะกรูดอบแห้ง/
    └── ...
```

## ไฟล์ใน repo

| ไฟล์ | รายละเอียด |
|---|---|
| `index.html` | หน้าเว็บ (ขึ้น GitHub Pages) |
| `apps-script/Code.gs` | ระบบหลังบ้านบน Google Apps Script ที่เก็บข้อมูลและไฟล์ลง Drive |

## วิธีติดตั้ง (ทำครั้งเดียว ประมาณ 10 นาที)

ให้ใช้บัญชี Google ที่เป็นเจ้าของโฟลเดอร์ **RA ตรวจสินค้าใหม่**

### 1. สร้าง Apps Script

1. เปิด https://script.google.com แล้วกด **New project** (โปรเจกต์ใหม่)
2. ตั้งชื่อโปรเจกต์ เช่น `RA ตรวจสินค้าใหม่`
3. ลบโค้ดเดิมในไฟล์ `Code.gs` ทั้งหมด แล้ววางโค้ดจาก [`apps-script/Code.gs`](apps-script/Code.gs) แทน
4. ตั้งรหัส 2 ตัว (บรรทัด 19–20) ห้ามซ้ำกัน
   - `const TEAM_KEY = 'CHANGE-ME';` → **รหัสฝ่ายจัดซื้อ**: สร้าง แนบไฟล์ ส่งงานได้ แต่ Approve/Reject ไม่ได้
   - `const RA_KEY = 'CHANGE-ME-RA';` → **รหัส RA**: ตรวจ และ Approve/Reject ได้ (ให้เฉพาะ RA)
   > ⚠️ ห้ามใส่รหัสจริงลงใน GitHub ให้แก้ใน Apps Script เท่านั้น
5. กด 💾 บันทึก

4.1 ใส่อีเมลแจ้งเตือน (บรรทัด 21–22)
   - `RA_EMAILS` → อีเมล RA ได้รับแจ้งเมื่อจัดซื้อส่งงาน
   - `BUY_EMAILS` → อีเมลจัดซื้อ ได้รับแจ้งเมื่อ RA Approve / Reject
   - ใส่หลายคนได้ เช่น `['a@company.com', 'b@company.com']`

### 2. อนุญาตสิทธิ์ Drive และอีเมล

1. ที่แถบด้านบน เลือกฟังก์ชัน **setup** แล้วกด **▶ Run**
2. จะมีหน้าต่างขอสิทธิ์ กด **Review permissions** แล้วเลือกบัญชี Google
3. ถ้าขึ้นว่า "Google hasn't verified this app" ให้กด **Advanced** แล้วกด **Go to RA ตรวจสินค้าใหม่ (unsafe)** แล้วกด **Allow**
   (ขึ้นแบบนี้เพราะเป็นสคริปต์ที่เขียนเอง ไม่ใช่แอปที่ส่งให้ Google ตรวจ)
4. เมื่อรันเสร็จ ในโฟลเดอร์ RA ตรวจสินค้าใหม่ จะมี Google Sheet **สรุปรายการสินค้า** ขึ้นมา

### 3. Deploy เป็น Web app

1. กด **Deploy** (มุมขวาบน) แล้วกด **New deployment**
2. กดรูปเฟือง ⚙ ข้าง "Select type" แล้วเลือก **Web app**
3. ตั้งค่า
   - **Execute as:** Me (บัญชีของคุณ)
   - **Who has access:** Anyone
4. กด **Deploy** แล้วคัดลอก **Web app URL** (ลงท้ายด้วย `/exec`)

### 4. เชื่อมหน้าเว็บ

1. เปิด https://naweevar-ui.github.io/New_Product/
2. กด **⚙ ตั้งค่า** แล้วใส่
   - ชื่อของคุณ
   - รหัสเข้าใช้: ฝ่ายจัดซื้อใส่ `TEAM_KEY` ส่วน RA ใส่ `RA_KEY`
   - URL ของ Apps Script จากข้อ 3
3. กด **บันทึกและเชื่อมต่อ**

ส่งลิงก์เว็บและ**รหัสจัดซื้อ**ให้ฝ่ายจัดซื้อ (URL ของ Apps Script ใส่ไว้ใน `index.html` แล้ว)
ระบบจะรู้เองจากรหัสว่าเป็นจัดซื้อหรือ RA: ฝ่ายจัดซื้อจะไม่เห็นแท็บ RA และระบบหลังบ้านไม่ยอมให้รหัสจัดซื้อ Approve/Reject

### ถ้าแก้โค้ด Apps Script ภายหลัง

กด **Deploy → Manage deployments → ✏️ แก้ไข → Version: New version → Deploy** (URL เดิมยังใช้ได้)

## ขั้นตอนการทำงาน

1. **ฝ่ายจัดซื้อ** กรอกข้อมูลให้ครบ 4 ส่วน
   - ชื่อสินค้า (ใช้เป็นชื่อโฟลเดอร์ใน Drive)
   - Ingredient: แนบไฟล์ (PDF / รูปภาพ / .txt) และติ๊กยืนยันว่าในไฟล์รวมครบ **100%**
   - Nutrition: แนบไฟล์
   - Process Flow: แนบไฟล์

   ถ้าขาดส่วนใดส่วนหนึ่ง หรือ Ingredient รวมไม่ถึง 100% ปุ่ม "ส่งให้ RA ตรวจ" จะกดไม่ได้
2. **RA** เห็นไฟล์ Ingredient ก่อน ตรวจแล้วกด
   - **Approve**: กดได้เมื่อข้อมูลครบ และ RA ติ๊กว่าตรวจไฟล์ Ingredient แล้ว
   - **Reject**: ต้องใส่เหตุผล งานจะถูกส่งกลับให้จัดซื้อแก้ไขแล้วส่งใหม่

## การแจ้งเตือนทางอีเมล

| เหตุการณ์ | ส่งถึง |
|---|---|
| จัดซื้อกด "ส่งให้ RA ตรวจ" | RA (`RA_EMAILS`) |
| RA กด Approve | จัดซื้อ (`BUY_EMAILS`) |
| RA กด Reject | จัดซื้อ (`BUY_EMAILS`) พร้อมเหตุผลและส่วนที่ต้องแก้ |

อีเมลส่งจากบัญชี Google ที่ติดตั้ง Apps Script (บัญชี Gmail ทั่วไปส่งได้ 100 คนผู้รับต่อวัน)

## ข้อจำกัด

- ไฟล์แนบได้ไม่เกิน 10 MB ต่อไฟล์
- รายการในหน้าเว็บจะดึงข้อมูลใหม่ทุก 20 วินาที ไม่ได้อัปเดตทันที
